# Спецификация: «Сохранённые поиски авто»

Нормативное описание поведения. Если код и документ расходятся, сначала обновляется
документ, затем код. Мотивация решений — в [README](../README.md), соглашения кода —
в [style.md](style.md).

## 1. Назначение и рамки

Приложение показывает каталог автомобилей, позволяет отфильтровать и отсортировать
его, сохранить поиск и увидеть, сколько новых лотов появилось после сохранения.

**Входит:** каталог, фильтры, сортировки, сохранённые поиски, счётчик новых,
имитация добавления лотов, адаптивный интерфейс, тесты, статический деплой.

**Не входит:** бэкенд, авторизация, сетевые запросы в рантайме, редактирование лотов,
мультиязычность, тёмная тема, E2E и визуальные регрессии.

## 2. Данные

Источник — открытый API `b.abw.by` (`/api/v2/cars/list?page=N`, 20 записей на страницу).
Скрипт `scripts/fetch-lots.ts` (`npm run data`) забирает страницы 1–20, дедуплицирует
по `id`, берёт 300 объявлений с фотографией и пишет:

- `src/data/lots.json` — массив лотов;
- `public/photos/<id>.webp` — по одной фотографии 640×480, webp, q70.

Приложение не ходит в сеть: JSON импортируется динамическим чанком, фото лежат рядом.
`src/data/lots.json` и `public/photos/*` руками не правятся.

**Правила парсинга:**

| Поле | Источник |
| --- | --- |
| `make` | слаг из `link` (`/cars/detail/{make}/{model}/{id}`) задаёт число слов; написание — из `title` |
| `model` | `title` без года, марки, «Рестайлинг» и скобок с кодом поколения |
| `year` | последние 4 цифры в `title` |
| `priceUsd` | `price.usd` |
| `mileageKm` | первое число в `params[0]` |
| `bodyType` | `params[3]` |
| `city` | `city` |
| `appearedAt` | `updated_at` через `parseAbwDate`; иначе `now − index × 3 ч` |
| `photo` | `images.list[0].xl`, скачивается и пережимается |

`updated_at` приходит строкой («27 минут назад», «сегодня в 17:12», «5 Ноября 2026»).
`parseAbwDate` поддерживает эти форматы и возвращает `null` на незнакомом — приложение
не падает из-за изменения формата на стороне API.

## 3. Модель

```ts
type SortKey = 'newest' | 'cheapest';

interface Filters {
  make?: string;
  yearFrom?: number;
  yearTo?: number;
  maxPrice?: number;
}

interface Lot {
  id: string;
  make: string;
  model: string;
  year: number;
  priceUsd: number;
  mileageKm: number;
  bodyType: string;
  city: string;
  photo: string;
  appearedAt: string;
}

interface SavedSearch {
  id: string;
  name: string;
  criteria: { filters: Filters; sort: SortKey };
  createdAt: string;
  lastSeenAt: string;
}
```

`photo` — путь относительно `BASE_URL`, например `photos/27405864.webp`.
`appearedAt`, `createdAt`, `lastSeenAt` — ISO-строки.

## 4. Поведение

**Фильтры.** Условия объединяются по И. Границы включительные. Отсутствие поля —
отсутствие ограничения. Если `yearFrom > yearTo`, границы меняются местами.

**Нормализация.** Перед сохранением и записью в URL `normalizeFilters`:

- убирает пустую марку и `maxPrice <= 0`;
- убирает границу года, совпадающую с минимумом/максимумом данных;
- полный диапазон годов превращает в отсутствие фильтра.

**Прокрутка.** После изменения фильтров или сортировки, если набор карточек изменился,
каталог плавно прокручивается к началу списка. Пагинация «Показать ещё» прокрутку не
вызывает.

**Сортировки.**

- `newest` — `appearedAt` по убыванию, тай-брейк — `priceUsd` по возрастанию;
- `cheapest` — `priceUsd` по возрастанию, тай-брейк — `appearedAt` по убыванию.

Сортировка не мутирует исходный массив и детерминирована при равных ключах.

**Сохранение поиска.** Сохраняется снимок нормализованных фильтров и сортировки,
`name` генерируется из условий (`describeCriteria`), `createdAt = lastSeenAt = now`.
Если такой же поиск уже есть (совпадают фильтры и сортировка), второй не создаётся:
показывается уведомление «Такой поиск уже сохранён». Имя пустого поиска — «Все лоты».

**Счётчик новых.** `countNewLots` считает лоты, у которых `appearedAt > lastSeenAt`
и которые подходят под фильтры поиска. Сортировка на счётчик не влияет. Открытие
поиска ставит `lastSeenAt = now`, счётчик обнуляется, каталог плавно прокручивается
к началу. При нуле показывается «Нет новых», а не скрытый бейдж. В навигации число
не обрезается.

**Добавление лотов.** Кнопка «Добавить 5 новых» генерирует 5 лотов:

- марка, модель, кузов, город и фото — у случайного базового лота;
- год — год донора −4…+2, но не раньше 1990 и не позже текущего;
- цена — 3 000…55 000 с шагом 100;
- пробег — 10 000…380 000 с шагом 1 000;
- `appearedAt = now − index` мс, `id` уникален в пределах вызова.

Лоты сразу попадают в каталог и увеличивают счётчики. Всего хранится не более 1 000
добавленных лотов: при превышении удаляются самые старые, пользователь получает
уведомление.

## 5. Хранилище

- Базовые лоты в `localStorage` не хранятся.
- Ключи с версией схемы: `autosearch.v1.searches`, `autosearch.v1.lots`.
- Запись обёрнута в `try/catch`: при ошибке квоты показывается уведомление,
  приложение продолжает работать в памяти.
- Чтение валидируется по форме; битые данные сбрасываются без падения.
- Синхронизация между вкладками — через событие `storage`.
- Удаление поиска можно отменить: поиск возвращается на прежнюю позицию.

## 6. Интерфейс

**Маршруты.** `createHashRouter`: `/` — каталог, `/searches` — мои поиски, `*` — 404.
Hash выбран, чтобы GitHub Pages не требовал копию `index.html` в `404.html`.

**URL.** Фильтры и сортировка живут в query-параметрах: `make`, `yearFrom`, `yearTo`,
`maxPrice`, `sort`. `sort=newest` не пишется. Обновление — `replace: true`.

**Загрузка.** `lots.json` — отдельный динамический чанк. До готовности показываются
скелетоны каталога, панели фильтров, тулбара и счётчика; у фотографии — скелетон
до `onLoad`/`onError`.

**Раскладка.**

- Десктоп от 992 px: фильтры в липкой колонке слева, карточки в 2–3 колонки.
- Мобильные до 991 px: фильтры в нижней шторке, нижняя навигация 64 px, одна карточка
  в ряд. Нижний отступ контента — 64 + 24 px + `safe-area-inset-bottom`. Шапка,
  навигация и нижняя шторка учитывают safe-area.
- Тулбар «фильтры — найдено — сортировка» на мобильных липнет под шапкой (top 64 px),
  прячется при прокрутке вниз и возвращается при прокрутке вверх. Высота 52 px:
  36 px контролы + по 8 px сверху и снизу; снизу ещё 16 px до сетки.

**Фильтры.**

- Марка — Mantine `Select` с поиском и очисткой; в липкой панели и шторке —
  `floatingStrategy: 'fixed'`, `width: 'target'`.
- Год — `RangeSlider`; значение применяется по `onChangeEnd`.
- Цена — `TextInput`; во время фокуса показываются только цифры, маска появляется
  по blur/Enter. Применение адаптивное: пауза 250 мс при быстром вводе, при паузе
  больше 400 мс — сразу; первое значение также проходит паузу 250 мс.
- В шторке фильтры — черновик: применяются по «Показать N», «Следить» применяет
  и сохраняет. На десктопе — сразу.

**Сортировка.** Один `SegmentedControl` с подписями «Новые» и «Дешевле» на всех
экранах; на мобильных шрифт 12 px и горизонтальные отступы 4 px, на десктопе —
14 px и 8 px.

**Размеры.** Сетка 4 px: шапка и навигация 64, контролы 36, тулбар 52, карточка 296,
панель фильтров 368, фото 180. Строки текста 20/16/24 px, подписи полей 14 px / 500.
Рамки карточек и панелей — `box-shadow`, не `border`. Скелетоны совпадают с живыми блоками.

**Состояния и доступность.** Пустой каталог и пустые «Мои поиски» содержат действие.
Если чанк с данными не загрузился, показывается состояние ошибки с кнопкой «Повторить»,
а не бесконечный скелетон.
Ховеры — только в `@media (hover: hover) and (pointer: fine)`. Уважается
`prefers-reduced-motion`. Уведомления: снизу справа на десктопе, сверху по центру
в мобильной раскладке (до 991 px), ширина — `calc(100% - 32px)`. Счётчик
результатов и счётчики поисков объявляются через `aria-live="polite"`.

**Фотографии.** Если фото лота не загрузилось, карточка до пяти раз подставляет
случайное фото из базовых лотов (кроме текущего). Заглушка с текстом «Фото недоступно»
не используется; после исчерпания попыток показывается нейтральная иконка автомобиля.

**Даты.** «сегодня в 21:01», «вчера в 21:45», дальше «12 ноя 2026».

## 7. Тесты

`npm test` — 92 теста на vitest + Testing Library. Покрываются `parseAbwDate`,
`splitMakeAndModel`, `parseMileage`, `filterLots`, `sortLots`, `countNewLots`,
`normalizeFilters`, `generateLots`, `readJSON`/`writeJSON`,
`saveSearch`/`deleteSearch`/`markSearchSeen`, форматирование и UI-сценарии:
фильтрация, «Добавить 5», сохранение поиска, фильтры из шторки, очистка цены,
полный цикл «сохранил → добавил → счётчик → открыл → обнулился» и удаление с возвратом.
E2E и визуальные регрессии — вне рамок.

## 8. Сборка и деплой

`npm run build` = `tsc -b` + `vite build`. `base` вычисляется из `GITHUB_REPOSITORY`,
локально — `/`; ассеты подключаются через `assetUrl()`.

GitHub Actions:

- `ci.yml` — lint, typecheck, test, build на push и pull request;
- `deploy.yml` — lint, typecheck, test, build и публикация `dist` на Pages.

**SEO и метаданные.** `index.html` задаёт `lang="ru"`, description, robots, Open Graph
и Twittercard. `src/lib/pageMeta.ts` — заголовок и описание для каталога, «Моих поисков»
и 404; `usePageMeta` применяет их при смене маршрута. Разметка: `header`, `nav` и `main`
из `AppShell`, `section` для фильтров и результатов, `article` для карточек, `h1`
у каждой страницы. Иконки и OG-картинка — `public/favicon.svg`, `favicon-32.png`,
`apple-touch-icon.png`, `og.png`; генерируются `npm run icons`. `canonical`, `og:url`
и `og:image` подставляются при сборке: из `SITE_URL`, иначе из `GITHUB_REPOSITORY`
(`https://<owner>.github.io/<repo>`), локально — путь от `base`.

## 9. Ограничения

- Данные — снимок на момент генерации; `appearedAt` — дата обновления объявления,
  а не гарантированная дата публикации.
- Новые лоты синтетические и живут только в браузере пользователя.
- Цена и год применяются не на каждое событие, а по паузе/отпусканию — осознанный
  компромисс ради отзывчивости.
- Тёмная тема не проверялась: тема светлая, `colorScheme` зафиксирован.
