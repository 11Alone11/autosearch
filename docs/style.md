# Код-стиль

Правила для `src/`, `scripts/` и тестов. Документ описывает то, что уже принято
в проекте; новые исключения добавляются сюда, а не в комментарии к коду.

## Язык и имена

- Код, типы, файлы и идентификаторы — по-английски. Интерфейс, документация и
  названия тестов — по-русски.
- Компоненты и типы — `PascalCase`, функции и переменные — `camelCase`, константы —
  `UPPER_SNAKE_CASE`.
- Булевы значения начинаются с `is`, `has`, `can`, `should`; обработчики — с `on`,
  хуки — с `use`.
- Файлы компонентов — `PascalCase.tsx`, хуков — `useSomething.ts`, тестов —
  `*.test.ts` или `*.test.tsx`.
- Экспорты именованные. `default` используется только там, где его требует инструмент.

## Форматирование

- 2 пробела, одинарные кавычки, точки с запятой, висячие запятые.
- Ориентир по длине строки — 100 символов. Длинные русские строки интерфейса и
  названия тестов могут быть длиннее, если перенос ухудшает читаемость.
- Импорты: сначала внешние пакеты, затем внутренние модули; внутри группы —
  от общего к частному. Неиспользуемые импорты удаляются.
- Автоматического форматтера нет; форматирование поддерживается вручную и проверяется
  на ревью.

## Структура и ответственность

- `src/lib/` — чистые функции без React, DOM и побочных эффектов. Новая логика
  приходит с тестом.
- `src/state/` — единственное место, где читается и пишется `localStorage`.
- `src/hooks/` — переиспользуемые хуки без доменной логики.
- `src/components/<раздел>/` — отображение и локальное состояние компонента.
- `src/pages/` — композиция компонентов и вызовы `lib`/`state`; бизнес-логики здесь нет.
- `src/data/lots.json` и `public/photos/*` генерируются скриптом. Руками не правятся.
- Один компонент — один файл. Пропсы описываются `interface` рядом с компонентом.
- Страница не знает о внутренностях хранилища, а `lib` не знает о React.

## Типы

- `strict: true`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`.
- Запрещены `any`, `@ts-ignore`, `@ts-expect-error` и необоснованные `as`.
- Внешние данные (JSON, `localStorage`, ответ API) сначала валидируются, потом
  приводятся к типу через type guard.
- Объектные пропсы и доменные сущности — `interface`; союзы и утилитарные типы — `type`.
- Для вариантов результата используется дискриминированный союз
  (`{ status: 'saved' } | { status: 'duplicate' }`), а не набор необязательных полей.

## Функции

- Ранний выход вместо вложенных условий; глубина вложенности — не больше двух.
- Одна функция делает одно; побочные эффекты отделены от вычислений.
- Параметры-опции — объектом с значениями по умолчанию, если их больше двух.
- Магические числа выносятся в именованные константы.
- Ошибки не глотаются: пользователю показывается понятное сообщение, приложение
  продолжает работать в памяти.

## React

- Только функциональные компоненты. Хуки — в начале компонента, без условий.
- React Compiler включён: `memo`, `useMemo` и `useCallback` не добавляются «на всякий
  случай». Исключение — вычисления по массиву из 300 лотов и реальная зависимость от
  стабильной ссылки.
- Эффекты — только для синхронизации с внешним миром (подписки, DOM, скролл).
  Вычисляемое состояние выводится в рендере. `useSyncedDraft` намеренно использует
  синхронизацию состояния в рендере по паттерну React — это единственное исключение.
- Состояние, меняющееся на скролле, не хранится в React: класс переключается через ref.
- Ключи списков — стабильные `id`, не индексы.
- `Card.Section` — прямой потомок `Card`; обёртка компонентом ломает отступы Mantine.
- Контроли не теряют фокус и не меняют высоту при вводе.

## Данные и состояние

- Источник истины для фильтров — URL; для сохранённых поисков и добавленных лотов —
  `localStorage`; базовые лоты — бандл.
- Любое изменение фильтров проходит через `normalizeFilters`.
- «Новый лот» — это `appearedAt > lastSeenAt` и совпадение с фильтрами, не `id`.
- Часто меняющийся ввод не пишет в URL на каждое событие: локальный черновик плюс
  `onChangeEnd`, debounce или фиксация по blur/Enter.
- Сортировки детерминированы: у каждой есть тай-брейк.

## Стили

- Mantine — единственный UI-кит и источник компонентов.
- Свой CSS — только `src/styles/global.css` (дизайн-слой) и `src/theme.ts` (дефолты).
  Новые `.css`-файлы и переписывание компонентов «с нуля» не добавляются.
- Единицы — px; внутри Mantine — rem. `em` в своих стилях и медиа-запросах нет.
- Все размеры кратны 4 px. Высоты контролов — 36 px (`size="sm"`), подписи полей —
  14 px / 500, строки текста — 20/16/24 px.
- Рамки карточек и панелей рисуются `box-shadow`, а не `border`: border добавляет
  2 px и ломает паритет скелетонов.
- Ховеры — только в `@media (hover: hover) and (pointer: fine)`.
- Уважается `prefers-reduced-motion`.
- Инлайн-стили допустимы для позиционирования и CSS-переменных, но не для цветов,
  отступов и типографики, которые уже есть в дизайн-слое.

## Тесты

- Тесты лежат рядом с кодом и проверяют поведение, а не реализацию.
- Запросы — по роли, подписи или тексту; `data-testid` — только когда иначе не найти.
- Тест не зависит от текущей даты и порядка `Math.random`; время и случайность
  передаются параметрами.
- Снапшоты не используются. Тест должен падать, если сломать функцию.
- Названия тестов — по-русски, в утвердительной форме: «считает только подходящие лоты».

## Комментарии

- Комментариев в коде нет. Причина решения, компромисс или неочевидное поведение
  описываются в `docs/spec.md` или `README.md`.
- TODO/FIXME и закомментированный код не хранятся в репозитории.

## Коммиты и проверки

- Формат: `feat:`, `fix:`, `test:`, `docs:`, `chore:` + короткое описание по-русски.
- Один коммит — одна законченная мысль.
- Перед коммитом: `npm run lint && npm run typecheck && npm test && npm run build`.
- Для изменений карточки, панели, тулбара или скелетона — ещё `npm run check:grid`
  при запущенном `npm run dev`.
